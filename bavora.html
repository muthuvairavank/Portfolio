01 / OVERVIEW

A clearer path to a trip.

Bavora is a travel planning design concept that brings package discovery, comparison, and trip planning into one experience. The core idea is to present the same information consistently, so travelers can understand what each package includes.

My contribution

  • Designed package discovery, comparison, trip planning, and booking confirmation flows.
  • Created desktop and mobile UI layouts in Figma.
  • Used Auto Layout and reusable components to keep screens consistent.
  • Organized package information and navigation around the comparison task.

02 / THE PROBLEM

Same destination.
Different information.

Travelers find it difficult to compare packages when prices, hotels, activities, and inclusions are presented in different formats. A lower price alone doesn’t explain which package best fits their needs.

How might we help travelers compare the details that matter without moving back and forth between separate package pages?

03 / THE APPROACH

Give every option
the same structure.

The design uses shared comparison categories: price, duration, hotel, transport, meals, and activities. These categories provide a common structure for evaluating different packages.

Discover→View details→Compare→Plan→Confirm

This illustrates a journey through the designed screens. The portfolio presents the concept; it does not process travel bookings.

04 / DESIGN DECISIONS

The details behind
the screens.

01 — Compare like for like

Use the same categories in the same order for every package. The intent is to make differences easier to spot, instead of asking travelers to remember details from previous pages.

02 — Put key information first

Price and duration lead the package information, followed by what is included. Secondary details come later, supporting both a quick scan and a deeper look.

03 — Keep the next step clear

Discovery, evaluation, and planning each have a distinct purpose. Navigation and calls to action help people move between those stages without losing their place.

04 — Design for smaller screens

Desktop and mobile layouts share the same visual language. On smaller screens, information needs a clear reading order and readable text. The comparison experience still needs testing with real travelers.

Design reasoning

The page moves from inspiration to practical choices. Travel imagery creates context; repeated calls to action provide routes into the task.

Narrow a large set of options

What the screen does

Search controls sit above a filter sidebar and a grid of package cards. Filters cover destination, budget, duration, and other travel preferences. Cards expose a price, key inclusions, and separate detail and comparison actions.

Design reasoning

Consistent card structure supports scanning. Keeping filters beside the results makes the relationship between preferences and available packages visible.

What the screen does

This additional listing screen shows more package cards, persistent filter categories, and pagination. The card format carries through the longer results view.

Design reasoning

Repeated layout patterns allow travelers to continue browsing without learning a new presentation for every option.

05

Side-by-side comparison

Compare what the price includes

Side-by-side comparison · Select to enlarge · Scroll inside the frame to see the complete page

What the screen does

Three package columns share rows for overview, stay, transport, meals, activities, policies, and support. A package selector and add-package action sit above the comparison. Each option has its own next-step action.

Design reasoning

Aligned categories make differences visible across packages. A shared row structure reduces the need to remember details from separate pages; testing would establish whether it makes decisions easier.

THE USER JOURNEY

Make the trip your own

Support both a package-led route and a more personalized planning route.

06

Plan your trip

Turn preferences into a trip outline

Plan your trip · Select to enlarge

What the screen does

Despite the export filename, this screen is a trip-planning form. It collects destinations and other trip preferences, displays a route preview, and places a trip summary in a separate right-hand panel.

Design reasoning

The form and summary sit together so travelers can review the emerging plan alongside their inputs. The route image gives a visual reference for the selected destinations.

07

Consider worthwhile stops

Explore along the route · Select to enlarge

What the screen does

A central map is framed by suggested places on the left and selected places on the right. The selected-place panel includes a trip-impact summary and a route update action.

Design reasoning

This layout makes geography part of the planning task. Suggested stops, current selections, and the route are visible in one workspace.

THE USER JOURNEY

From selection to confirmation

Keep the chosen package and booking context visible as details are collected.

08

Traveller details

Collect information in manageable groups

Traveller details · Select to enlarge · Scroll inside the frame to see the complete page

What the screen does

A selected-package card leads into traveller details, contact information, special requests, room preferences, and a promo-code field. A separate booking summary displays a cost breakdown and continuation action.

Design reasoning

Related fields are grouped into sections. The package and total provide context while travelers complete the form. Validation, payment behavior, and error handling are not established by this static screen.

09

Booking confirmation

Make the result unmistakable

Booking confirmation · Select to enlarge

What the screen does

A green success mark, confirmation headline, booking reference, and View My Trip action establish the completion state. A supporting panel gives brief preparation guidance.

Design reasoning

The screen closes the booking journey with a clear status and a next step. It is a designed confirmation state, rather than evidence of an operational booking service.

After the booking

Help travelers return to their plans and manage the details.

10

Itinerary

Understand the day ahead

Itinerary · Select to enlarge · Scroll inside the frame to see the complete page

What the screen does

A destination summary and confirmation status lead into booking, document, and cost information. Day tabs organize a chronological activity timeline with times, descriptions, and supporting imagery.

Design reasoning

A time-based structure turns a long trip plan into smaller daily views. Status indicators and document information place operational details near the itinerary.

11

Profile

Bring personal travel information together

Profile · Select to enlarge

What the screen does

The profile screen groups a traveler header, trip and saved-place shortcuts, profile completion, payment-card information, and travel-service categories.

The layout is intended as an account overview. The identity, progress, and payment details shown belong to the interface mockup; they are not the designer’s personal profile.

Account & brand foundations

Supporting screens explain the service and provide entry points to an account.

12

Login

Return to an existing account

What the screen does

A compact email-and-password form is paired with a large destination image. Password recovery, social sign-in options, and a sign-up route sit around the primary login action.

Design reasoning

The split layout separates the task from the aspirational travel message. Authentication, recovery, and social-provider integrations would need implementation and testing.

The screen reuses the login page’s image-and-form composition, creating continuity between the two account-entry states.

14

About Bavora

Explain the service promise

About Bavora · Select to enlarge · Scroll inside the frame to see the complete page

What the screen does

The page introduces Bavora, describes its comparison approach, and presents mission and values, a process section, and routes back into planning and package discovery.

The content supports understanding of the product. Numerical counters, ratings, and other promotional claims visible in this concept artwork are illustrative and are not verified business results.

06 / REFLECTION

What I learned.
What comes next.

Clarity starts with the information.

This project helped me think beyond individual screens. Defining common categories gave the comparison view a clearer structure and helped guide decisions across the experience.

The next step is testing.

I would ask travelers to compare packages and explain their choice. I’d observe which details they look for, where they hesitate, and whether the mobile layout supports the same task comfortably.

This is a self-directed design project. The supplied screens establish the visual concept, not a tested live service. No measured usability improvements or research results are claimed.

What I would refine next

  • Test comparison on a small screen, including how travelers keep the category labels in view.
  • Standardize currencies, destinations, and sample trip details across the connected journey.
  • Validate form errors, keyboard access, text contrast, and loading states in an interactive prototype.
  • Clarify the difference between choosing a ready-made package and building a custom trip.
